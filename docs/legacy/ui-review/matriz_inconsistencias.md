# Matriz de Inconsistências de UI/UX — D'Luxury CRM

Esta matriz relaciona os desvios visuais identificados nas fases iniciais de auditoria e a resolução técnica adotada.

| Categoria             | Descrição do Desvio / Inconsistência                                                                                                 | Impacto                                                                     | Resolução Técnica no Design System                                                                                                                                                   |
| :-------------------- | :----------------------------------------------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Card**              | Cards com bordas cinzas claras, fundos inconsistentes (`bg-[#1c1c1e]`, `bg-[#2c2c2e]`), cantos retos e paddings variáveis nas telas. | Baixo contraste e quebra de unidade visual.                                 | Criação do componente `<Card>` base unificado com variante `default` (borda HSL `--border`, fundo HSL `--card`, cantos `rounded-2xl` e paddings utilitários `p-6`).                  |
| **Modal / Janela**    | Modais sem suporte a fechamento automático via tecla `ESC` ou clique no overlay (fundo).                                             | UX prejudicada (frustração de interação).                                   | Centralização do componente `<Modal>` com `useEffect` para escuta de `keydown` do `Escape`, controle de cliques externos e gerenciador de scroll do `body`.                          |
| **Modal / Foco**      | Ao abrir modais, o foco permanecia no botão de disparo e permitia interagir com o fundo. Ao fechar, o foco se perdia.                | Acessibilidade crítica (falha na navegação por teclado e leitores de tela). | Implementação de Focus Trap nativo no `<Modal>` (foca automaticamente no primeiro elemento editável e impede saídas via `Tab`).                                                      |
| **Botão**             | Variedade de classes Tailwind ad-hoc para cores de destaque e hover (`bg-orange-600`, `bg-amber-600`, `hover:bg-orange-700`).        | Visual desalinhado e estados de clique imprevisíveis.                       | Componente `<Button>` com variantes semânticas: `primary` (orange-accent), `secondary` (gray-surface), `outline`, `ghost` e `danger`. Estados `disabled` e `isLoading` padronizados. |
| **Scrollbar**         | Barras de rolagem com estilo padrão do Windows/Chrome (cinza claro), contrastando agressivamente com a UI escura.                    | Poluição visual e quebra de imersão.                                        | Customização global via CSS (`::-webkit-scrollbar`) aplicando largura de `8px`, trilho invisível e cor base do `--border` com transição para `--primary` no hover.                   |
| **Cores / Contraste** | Cores hexadecimais embutidas (`#fff`, `#000`, `#111`) impedindo suporte a temas dinâmicos e reduzindo contraste WCAG.                | Legibilidade comprometida para usuários com baixa visão.                    | Substituição completa por variáveis CSS baseadas em HSL (`hsl(var(--background))`, `hsl(var(--foreground))`, etc.), mapeando perfeitamente os temas Dark e Light.                    |
| **Inputs**            | Inputs com estilos e paddings inconsistentes, labels mal posicionados e tratamentos de erro manuais.                                 | Dificuldade no preenchimento e validação de formulários.                    | Centralização do componente `<Input>` encapsulando states de erro (`variant="error"`), labels de acessibilidade e textos auxiliares.                                                 |
